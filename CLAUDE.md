# CLAUDE.md

Мод Claude Code `limits-log`: журнал лимитов подписки (5h/7d) в JSON Lines и отчёт `/limits`.
Мод — плагин с модулем хуков на TypeScript (`hooks/register.tsx` — все хуки событий сессии, по
одному на событие: движок не принимает два без матчера; `log.ts` — записи `limits`; `sessions.ts` —
итоги сессий, записи `session` и `usageTotals`; `panel.tsx` — `/limits`; `analysis.ts` — анализ по
неделям, только данные; `view.ts` — тексты строк панели; `format.ts` — время и числа; `files.ts` —
формат журнала, чтение (с удалением повторов) и запись; `tokens.ts` — подсчёт токенов),
API — `.claude-plugin/types/`
(генерирует движок при загрузке, в git не идёт). Справка по модам — скилл `plugin-authoring`.

**Миграций в моде нет и не будет:** читатель понимает все версии формата журнала, старые записи
не переписываются.

## Как устроено

- Все файлы мода — в папке `limits-log/` каталога профиля (`MOD_DIR`). Журнал —
  `limits-log/log/<месяц UTC>/<сессия>.jsonl`. **Параллельные сессии — обычный режим, поэтому у
  сессий нет общего изменяемого места:** файл пишет только его сессия (по очереди внутри процесса,
  `appendRecord`), итог в `$.store` — тоже только своя сессия. Сводит читатель (`toRows`):
  сортирует записи всех сессий, отбрасывает повторы (то же состояние окон) и запоздавшие ответы
  (ниже процентов предыдущей записи при тех же сбросах, в пределах 5 мин), считает токены и ходы
  между записями как разницу `usageTotals` по сессиям. Новые данные — по тому же принципу:
  пишем абсолютные значения своего, разницу считает анализ.
- Журнал — JSON Lines, типы `LimitsRecord` и `SessionRecord` в `files.ts`, поля описаны в README.
  Мод пишет `v: 4` (`usageTotals`); `v: 3` — `usageSince`; `v: 2` — первая версия мода
  (без токенов и `session`); `v: 1` — данные, перенесённые из старого CSV. Формат только
  дополняется: поля не переименовывать и не
  менять смысл, читатель обходится без любого поля и пропускает незнакомый `kind`; при смене
  набора полей — следующая `v`. `windows` — все окна из ответа API; анализ берёт `five_hour` и
  `seven_day`. `effort` — из `turn.step` основного цикла (переменная модуля). Fast mode модам не виден.
- Итоги сессий (`sessions.ts`): у каждой сессии свой накопительный итог `session:<id>` в
  `$.store`, внутри сессии — по очереди (`mutate`). Запись `limits` кладёт итоги всех сессий в
  `usageTotals` (`allTotals`, только чтение). `session.end` пишет запись `session` в файл сессии
  и ставит `endedAt`; итог хранится ещё 24 ч, чтобы попасть в записи `limits`, затем
  `tidySessions` при `session.start` его удаляет. Не дошедший `session.end` — итог молчит дольше
  12 ч, `tidySessions` дописывает его в файл брошенной сессии как `reason: "orphan"`; ожившая
  сессия снимает `endedAt` (`mutate`) и пишет итог ещё раз. Из записей `session` с одним id верна
  последняя (итог накопительный).
- Запись в файл — только если он читается или его нет: нечитаемый файл не перезаписывается.
- Стоимость в анализе — `spent` из `toRows`: приросты `costUsd` по всем записям (повторы тоже),
  меньший `costUsd` — новый процесс (resume); «$ за 1%» делится на прирост 7d записей со `spent`.
- Запись — на событие `session.measure` при `changed` с `rateLimits` (окно сдвинулось на целый
  процент). Оно приходит только в сессию, получившую ответ API, поэтому фильтр простаивающих
  сессий не нужен; меньший процент — сброс вне расписания, пишется.
- Не пишется: нет окон; какое-то окно закончилось; те же окна, что в последней записи этой
  сессии (переменная модуля `lastState` в `log.ts`; после перезагрузки возможен повтор — его
  уберёт читатель).
- `/limits [now|week]` — панель со снимком анализа на момент открытия (`r` пересчитывает),
  режимы переключаются и клавишами `n`/`w`. Неделя — окно 7d по `d7_resets_at`.
  - День недели везде — 24 часа от начала окна 7d (`dayOf` в `analysis.ts`), не календарный.
  - `now` (по умолчанию; свои компоненты `NowWeek`, `NowH5`, не `WeekBody`): неделя — период и
    процент, полосы дней «Поровну» и «По N прошлым неделям» (последние законченные, до 5 — `PAST_WEEKS`; по ним же «Запас») (`DayBudget`, `dayBudgets`; во всю ширину панели
    по `e.props.bodyColumns`), строки «слово-статус значение» (`status` в
    `view.ts`): сброс, сегодня, можно, запас (по среднему приросту законченных недель или темпу
    этой), цена 1%, остаток, потрачено, модели; по дням; затем окно 5h — с и по, полоска,
    остаток, кончится.
  - `week`: вкладки законченных недель (последняя первой, клавиши 1–9; текущая — только в
    `now`): прирост по дням,
    окна 5h, стоимость, сообщения. «Сообщение» в панели — ход основного цикла (`turn.complete`
    без `agentId`), не точное число сообщений пользователя.
  - Общего анализа по всем неделям (`all`) пока нет — его добавим позже.
- Мод пишет только в сессиях, где он загружен, поэтому его подключают ко всем сессиям профиля
  (`CLAUDE_CODE_PLUGIN_DIRS`, см. README).

## Разработка

- Запуск: `claude --plugin-dir .` из этой папки — мод перезагружается после каждой правки.
- Проверка: `claude plugin validate .`, тесты — `claude plugin test .`, типы —
  `npx -p typescript tsc -p .` (с тестами), форматирование —
  `npx prettier@3.3.3 --write hooks types tests` (конфиг `.prettierrc.json`).
- Тесты (`tests/`): `journal.test.ts` — сведение записей параллельных сессий (повторы,
  запоздавшие ответы, разница `usageTotals`) и токены; `sessions.test.ts` — запись через движок
  (хуки теста стоят за файлы, `$.store` и сессию; движок приводит пути к виду платформы);
  `analysis.test.ts` — недели, прирост, стоимость, прогноз. Меняя запись или чтение журнала —
  сначала тест на новый случай.
- Панель: что показать — функции `view.ts` (строка или `undefined`), как — компоненты
  `panel.tsx` (`Line` не рисует пустое). В снимке анализа (`types/index.d.ts`) — данные, не тексты;
  при смене его формы — новый `shape` атома `analysis`.
- Личное окружение и данные автора — в `CLAUDE.local.md` (не в git).
- Коммиты — Conventional Commits. Репозиторий — сам себе маркетплейс
  (`.claude-plugin/marketplace.json`): установка — `/plugin install limits-log --marketplace
  justcatboy/claude-code-limits-log`; пользователи получают то, что в `main`.
